## Behavior and error contract

A refresh child whose current authorization is superseded by validated accepted-observation lineage, exclusion or deactivation now commits `status = cancelled`, `stage = 3` and `completed_at` before raising an internal `_CancelledRefresh` subclass of the existing ManagedWorkspaceFailure. Its public code is the existing `stale_request`. Recovery catches only this distinct durable-cancellation class, in addition to its existing target_changed handling. It does not swallow other managed-workspace errors.

The parent processes all originally bound children before durably aggregating the result. Any cancellation yields a cancelled parent and stale_request on explicit replay. Cancellation takes precedence over a sibling's content conflict; individual conflict rows and owner conflict-resolution APIs remain intact. Pure content-conflict parents still report target_changed. No abandoned request receives a refreshed/materialized success receipt. Parent completion timestamps and child outcomes remain unchanged on replay, including after reopen, new publication, restore/unexclude and explicit resolution of later conflicts.

Original manifest children, paths, revisions and bodies remain bound. Caller, request/manifest digest, revision-body digest and original preimage guards run before cancellation classification. Accepted-head changes require a retained chain of completed owner accept_revision operations matching their revisions and the note's accepted/materialized state. Arbitrary rollback, path mismatch, altered authority, altered bodies/digests, missing/mismatched revision authority and altered preimages remain operation_replay_mismatch and are not converted into cancellation or content conflicts. Corrupt pending rows deliberately remain pending with an error; startup availability is restored only for legitimate supersession.

A proven accepted edit may also have renamed the note. That supersedes the old authorization without granting any write to either its original or successor path. Without that proof, a changed current path remains a hard mismatch. The immutable journal target stays validated against the parent binding. Root checks and the existing filesystem preimage/atomic-write guards remain in force for actual writes. Direct setup/materialization authorization and owner-conflict semantics remain unchanged.

Fresh refresh requests have no obsolete pending blocker. Active eligible notes still follow existing owner-divergence/conflict rules; inactive/excluded notes remain skipped. Restoring eligibility does not itself authorize an old cancelled write. A fresh request binds the later approved publication, with explicit resolution/materialization where the retained accepted and disk states diverge.
