2. Require existing exclusive runtime admission with no live peer; settle prior ingestion, source/history migrations and custody before mutation. A busy or unresolved predecessor refuses without starting the new migration. Do not infer successful custody from a missing file.
3. Use the existing caller-owned SQLite transaction and `BEGIN IMMEDIATE`. ## Authoritative state and identity

New engine tables are private state in the existing database. They store immutable accepted intent/receipts plus constrained mutable operation checkpoints and projections. SQLite transactions are the truth for activation and retraction; filesystem payload custody is checked evidence, not an independent activation flag. Private files use existing descriptor confinement and durability rules.

| New table family | Required key and invariant |
|---|---|
| `capture_lifecycle_operations` | Unique `(brain_id, operation_id)`, immutable operation kind/request bytes/request SHA-256/accepting issuer, bound preview evidence, ordered item intent and terminal receipt. Mutable checkpoint follows only the state machine below. No reuse of an ID for another operation kind or request. |
| `capture_sessions`, `capture_session_members` | Opaque engine-issued session ID, trusted creator binding, monotone membership version, open/sealed/retracted state; ordered unique `(session_id, ordinal)` and globally unique capture membership. Each capture belongs to at most one trusted session. Accepted retraction seals the session. |
| `consumer_import_scopes`, `consumer_import_archive_bindings` | Durable account-scope/import-namespace identity per provider and Brain, unique owner label per provider, registered evidence bindings. Archive digest/provider anchor cannot silently move between scopes. Preview-only registration is not a durable account scope. |
| `consumer_import_groups`, `consumer_import_revisions`, `consumer_import_segments` | Group key and current revision/version; immutable revision manifest, exact expected group/source/lifecycle/control coordinates and ordered segment intents/receipts. Unique group/revision identity and segment index. Pending membership never becomes a current source head. |
| `capture_retractions`, `session_retractions`, `consumer_import_barriers` | Append-only decision/receipt and exact affected capture or frozen membership. Consumer barrier records its cause and group key, blocking future importer activation without claiming that a historical capture is the newer head. No destructive delete or importer restore flag. |
| `capture_lifecycle_generation` | Singleton monotone `eligibility_generation`, initialized at zero and advanced atomically with eligibility mutations. This is an internal race fence, not a scoped public change counter. |

Table families describe required constraints, not executable SQL or a frozen SQL checksum. The first implementation slice must commit concrete DDL, DTO/catalog schemas and golden serialization fixtures together before admitting any new state. The contract must not be advertised as an implemented compatibility version before that slice passes.

Identifiers are engine-issued UUID4 strings with kind prefixes: `capsess_`, `impscope_`, `impns_`, `imprev_`, `capreceipt_`; operation IDs are owner-selected canonical lowercase UUIDs. Import `conversation_key` and `segment_key` remain the domain-separated hashes in `EXPORT-FORMATS.md`. Accepting issuer is the current engine-resolved Brain/issuer pair, never an archive field. Hashes are lowercase SHA-256 over exact canonical bytes from `portable_canonical_json_bytes`; no timestamp or file path creates identity or ordering authority.

The immutable request domain includes `contract:"ob.capture-lifecycle.v1"`, `kind`, `brain_id`, `issuer_epoch`, `operation_id` and a kind-specific payload. Payloads contain the complete intent, not only its body hashes: capture envelopes, manifest/selection, scope/privacy/replacement selection and expected coordinates. Transport secrets, preview expiry and observation time are excluded from semantic intent identity. The retained preview binding still proves which exact intent was approved. Reject unknown fields, duplicate keys, invalid types and noncanonical encodings at the persistence boundary.

## Operation states, replay and crash recovery

Import operation states are `reserved`, `custodied`, `materializing`, `ready`, `committed`, `conflict`, `halted`. Item outcomes and the operation checkpoint are separate: some conversations may already be committed when a later conversation conflicts or execution stops. `committed` means every item has a recorded outcome and no conflict; `conflict` is a completed mixed/conflict result; `halted` is a terminal stop that retains successful earlier items. An outcome of unchanged/no-text/retracted is explicit, not an invented capture receipt. Aggregate nonterminal state describes the earliest unfinished conversation in canonical plan order.

For each conversation, persist immutable segment intents first, then `reserved -> custodied -> materializing -> ready -> committed`. Custodied means every immutable segment envelope/body required for recovery is durably held and verified; materializing means checked capture files/receipts are being prepared; ready means the complete manifest and every segment receipt verify, with no current eligibility yet. Per-segment states are `reserved`, `custodied`, `materialized`. Any conversation may instead finish `unchanged`, `conflict`, `retracted`, `no_text` or `halted`. Terminal outcomes/receipts are immutable.

Replay order is authority admission, operation kind/ID plus complete intent equality, then reconciliation of accepted state, then freshness checks for new progress. A changed intent with an existing ID returns `operation_conflict`; it cannot reuse a prior preview. A completed exact replay returns its retained result before testing preview expiry or current source head. It performs no capture, membership append, activation or restore. Returning an old success is not a statement that the capture remains eligible now.

Normal import commit re-reads the bounded selected file and proves byte/normalized-plan equality before first reservation. For an accepted nonterminal operation, engine-custodied intent is sufficient for explicit owner recovery even after the input file or preview expires. Recovery revalidates current privacy, issuer, source/group versions and all tombstones before any new progress. A restored Brain or changed issuer may expose old receipts through current owner authority, but cannot resume the old issuer's unfinished intent; it must terminalize it as halted and require a newly approved operation for remaining work.

Status is read-only and needs no file or preview. It returns durable counts/item outcomes using the exact body-free DTO in `EXPORT-FORMATS.md`. The dedicated owner-local command `open-brain import-chat recover --operation-id <uuid> --json` resumes only an existing immutable intent; it accepts no replacement payload or override. It returns the same status DTO. No automatic daemon, boot-time admission or status read resumes imports. SIGINT stops at a durable boundary, preserves completed items and returns the specified interrupted envelope with operation ID; an accepted stop is not rollback.

`open-brain import-chat halt --operation-id <uuid> --json` is the explicit owner-local terminalization command. Under the operation's writer fence, reconcile any committed activation, mark every remaining conversation halted, seal its capture session if present, and append an immutable owner-halt checkpoint/terminal receipt atomically. Preserve completed conversations and all custodied evidence. It changes no accepted intent and makes no pending segment eligible. Repeated halt or halt of an already terminal operation returns retained status without changing its outcome. Halt/recovery concurrency uses the same operation checkpoint CAS; only one may progress. A new issuer may halt old unfinished work under current owner authority but cannot resume it. SIGINT leaves the last durable nonterminal checkpoint resumable; only explicit halt or a recorded terminal refusal ends recovery. The command returns the same body-free status DTO, with halted item counts and zero pending items; no file/preview is required.

Lost acknowledgement is reconciled using persisted receipt/checkpoint truth. A crash before reservation has no accepted operation. A crash after custody resumes verification/materialization rather than recapturing; a crash during SQLite activation has either the old head or the complete new head/receipt. A terminal halted operation cannot be reopened by replay. Files left by a failed staging attempt stay quarantined until an owner-authorized bounded cleanup validates their ownership and references.

## Group staging and activation

The parser submits a complete normalized plan through the engine interfaces in `EXPORT-FORMATS.md`. Per-segment delivery identity is `SHA256(C(["consumer-segment-delivery-v1", brain_id, operation_id, conversation_key, conversation_revision_sha256, segment_index, capture_request_sha256]))`. The engine assigns its reserved delivery prefix when adapting this digest to its own journal. Reusing a prefix does not authorize the unchanged source-intake publication path.

Before creating any segment file or ordinary capture row, reserve its capture ID and pending-group association durably. Group-aware materialization may reuse custody validation, normalization and immutable file writing, but must not promote a logical source head, publish a canonical page, create an approved copy or expose an ordinary capture success. `register_intake` needs an explicit group-aware path; unchanged `submit` repeated for each segment is prohibited. Raw local filesystem access by the owning OS user is outside API visibility; no claim of isolation from that user is made.

In one bounded activation transaction, verify all at-most-128 segment receipts and exact manifest, current authority/privacy, source/group head and lifecycle/control CAS, import/session barriers and source namespaces. Then publish every segment source/head, the complete current group membership, exactly one terminal conversation receipt and newly created capture session membership; advance relevant source/retrieval generations and `eligibility_generation` together. Old tail segments become historical in that same transaction. An incomplete replacement leaves the previous revision current. A source withdrawal or changed policy during staging refuses activation and retains pending evidence for explicit recovery/halt.

The preview's global eligibility generation is an internal revalidation fence, not a literal equality CAS for every later conversation. If it changes, revalidate the next conversation's full exact preimages, current authority/privacy and barriers within activation admission. Rebase that internal fence only when those bindings are unchanged; accept this operation's earlier session appends/scope registration solely by verifying its durable own activation receipts and exact resulting session version. A changed target head, session sealed/retracted by another operation, policy/authority or dependency still refuses. Rebase changes neither immutable intent nor selected outcomes. Unrelated eligible-state changes cannot make conversation two fail solely because conversation one advanced the global counter.

One import operation owns one engine-issued capture session, created at first new activation. Only **newly activated captures** enter its membership. Unchanged reimport outcomes reference old receipts without joining those captures to a new session. No-text/conflict/retracted outcomes create no membership. Each conversation activation appends its complete member list once and advances the session version once. The import status reports that undo targets new admissions from this operation; it does not promise to retract previously present unchanged content. Exact operation replay never appends again.

Import operations process conversations in canonical key order. Each conversation is atomic; an entire archive is not atomic. Successful earlier activations remain if a later item conflicts, cancellation occurs or storage fails. The summary/status records this partial outcome. Initial scope registration, its first archive binding and first successful conversation activation commit together; an operation with no admitted content does not leave an empty registered scope. An archive omitted from later input has no effect. An unchanged conversation returns retained revision mapping even if packaging bytes changed, after a fresh archive preview.

## Trusted sessions and retraction

Register sessions only through trusted engine/app context, with an owner-local producer or the approved grouped importer. Source text, parser-supplied IDs and ambient harness metadata cannot attach a capture. The first implementation exposes no agent session-mutation grant; later harness/connector adapters need their own reviewed trusted producer binding. Ordinary historical captures remain ungrouped. A session is bounded at 20,000 members; a full session seals and refuses further append rather than silently splitting identity. Importer content/segment bounds remain independently enforced.

New owner-local CLI family (not present at baseline):

```text
open-brain retract preview --capture <capture-id> --json
open-brain retract preview --session <session-id> --json
open-brain retract preview --preview-id <opaque-id> --item-page <integer> --json
open-brain retract commit --preview-id <opaque-id> --operation-id <uuid> --json
open-brain retract status --operation-id <uuid> --json
```

Exactly one target is required. Preview resolves current owner authority and binds Brain/issuer, exact ordered capture membership, membership version/digest, capture revisions, current source heads/lifecycle/control, group invalidation and dependent-page/approved-copy impact. It creates no lifecycle decision. Preview IDs are random opaque `retprev_` plus 43 unpadded base64url characters; 16 live previews per owner, one-hour lifetime. Commit performs operation replay before expiry/CAS, then refuses any changed dependency or membership. A session append after preview makes it stale. No prompt or parser runs under a writer lease.

Capture retraction adds a tombstone for that exact capture. Session retraction seals the exact session and atomically installs a session tombstone referencing its complete immutable membership snapshot. Membership cannot append after that commit. Eligibility tests the session tombstone immediately; it does not wait for 20,000 per-capture cleanup writes. Retained per-capture tombstone expansion, if used for indexing, is a rebuildable projection and runs in batches of at most128 with durable checkpoints. The authoritative session decision and successful receipt are already committed; interruption of projection cleanup cannot restore eligibility or turn the receipt into partial undo.

Do not retire a newer unrelated logical-source head because an old member was retracted. Preview lists that newer head separately. For a current imported conversation, any retracted member makes that revision incomplete and suppresses its entire current group from normal retrieval; the preview must show this full group effect. Exact tombstones still identify only the selected captures/session. For every affected import group, retain a future-import barrier with its retraction cause; a later import/repack/replacement cannot route around it. A barrier on a historical revision does not retroactively retire an already active newer group revision whose members were not selected. Restore/reactivation is outside v1; no force/reset/reimport flag bypasses barriers.

Reviewed canonical pages and delivered copies are not automatically edited, withdrawn, unpublished or deleted. Their dependency projection must report the retracted input and withhold current evidence where the existing authority requires an eligible source closure. Preview names impacted pages/copies without claiming recall of bytes already delivered. Immutable source history remains readable through existing owner history authority, subject to privacy and ordinary custody checks; retraction is not hard deletion or secure erasure.

Retraction preview DTO v1 has exact keys `dto_version:1`, `status:"preview"`, `preview_id`, `expires_at`, `target:{kind,id}`, `counts`, `items`, `item_page`, `item_pages`, `next_item_page`, `history_retained:true`. Counts are `selected_captures`, `already_retracted`, `current_groups_suppressed`, `newer_heads_preserved`, `dependent_pages`, `approved_copies`. Each item has exact keys `{kind,id,effect}`. Kinds are `capture`, `current_group`, `newer_head`, `dependent_page`, `approved_copy`; IDs are existing owner-authorized record/group identities. Capture effects are `retract`, `already_retracted`, `historical_only`; group effect is `suppress_current`; newer-head effect is `preserve`; page/copy effect is `dependency_retracted`. These entries identify the actual affected objects, not just counts. Sort by kind then ID, maximum100 items per zero-based page; counts cover the complete immutable impact set. Initial preview returns page0, at least one page even for an empty set, and nullable `next_item_page`. The read-only page command requires existing preview ID and current owner authority, returns this same DTO, revalidates preimages, refuses expiry/staleness/out-of-range and never changes selection or extends expiry. Body text and raw paths never appear in summaries. Full membership and impact set are internally bound to commit; output pagination cannot omit effects from approval/CAS.

Retraction commit/status DTO has exact keys `dto_version:1`, `status`, `operation_id`, `receipt_id`, `counts`, `history_retained:true`; status is `committed` or `operation_not_found` is an error. Successful atomic decision/receipt creation needs no public pending state. Count values match the accepted preview's effects. Errors use the importer's fixed failed/error envelope and exit conventions, with additional closed codes `unsupported_capability` for rejected authority and `not_found` for an unknown target. Stale membership/head returns `revision_changed`; changed operation intent returns `operation_conflict`; invalid page returns `invalid_arguments`. No external MCP/plugin/desktop retraction surface or automatic grant is added in v1.

## Shared eligibility and embedding consent

Shared engine eligibility first rejects unactivated pending segments **even for owner history**, then applies existing authority/privacy/custody. Normal current reads additionally reject capture/session tombstones, withdrawn sources and incomplete/replaced group membership. Owner historical reads may access admitted retracted evidence through existing history capability; that exception never admits pending staging. All search candidates, direct/history lists and reads, inbox/review sources, graph projection, approved-copy/provider delivery and cache/output release must use this distinction. A search-only WHERE clause is insufficient.

Eligibility changes include capture/session retraction, import activation, source lifecycle/availability, current head/membership, effective privacy/routing, relevant consent and authority changes. Increment `eligibility_generation` in each authoritative transaction affecting these facts, alongside existing generation mechanisms. Scoped public cursors bind only their authorized visible digest; unrelated hidden changes trigger internal revalidation, not a new public counter/oracle. Revalidate final output with the shared release mechanism. The bounded transport handoff requirements in `EMBEDDING-RESOURCE.md` apply to new hybrid output; this design does not claim the existing transports already implement them.

Local embedding consent is new explicit owner policy, separate from provider egress consent and model installation. Persist a versioned engine policy binding Brain/issuer, enabled state, selected component/policy digest and monotone consent version. Only owner-local CLI can change it; no imported body, helper or ambient credential enables it. First migration/restoration defaults to disabled. Disabling bumps eligibility/policy generation, prevents text release immediately and invalidates affected cache use; cache garbage collection does not gate revocation. Portable retains policy history as evidence but never re-enables execution on a restored host. Exact CLI/policy wire schema is a required G4 implementation contract, not guessed into existing provider-consent DTOs.

Internal hybrid failure categories map to existing public search contracts: unavailable/corrupt/incomplete resource/cache and failed currentness revalidation yield existing `model_unavailable` semantics; cursor binding mismatch yields existing `cursor_stale`; authority denial uses the existing closed permission/not-found behavior. `currentness_changed`, component hashes, cache counts and filesystem details remain internal/owner health information. If an existing DTO cannot express a required result, review a versioned extension before implementation; do not append values to frozen DTO1.

## Portable13 and restore

Portable13 inherits exact Portable12 evidence bytes and adds a versioned `ob.capture-lifecycle.v1` evidence family under `history/capture-lifecycle/`. Its canonical UTF-8 JSONL files are `operations.jsonl`, `sessions.jsonl`, `imports.jsonl`, `retractions.jsonl`, `embedding-policy.jsonl`; rows use exact typed schemas to be committed with the migration. Import envelopes/bodies required for terminal retained evidence live under `sources/import-custody/sha256/<first-two-hex>/<sha256>`, with no archive paths, original ZIPs, attachments or external URLs. The inventory covers every byte. Export all referenced immutable evidence, not only current captures.

Snapshot requires no nonterminal grouped import and no unfinished predecessor ingestion. Otherwise return owner-local `operation_pending` without mutation; the owner explicitly recovers or terminally halts first. Terminal halted operations include their intent, outcome/checkpoints and required held payload evidence as noncurrent retained history. Export may include admitted retracted captures and terminal quarantined custody; it must never reinterpret either as an active group. Lifecycle preview tokens, credentials/grants, live file descriptors, runtime sessions, embedding caches/vectors/query data and helper staging are excluded.

Before destination mutation, validate exact13 manifest/catalog, canonical row schemas, unique keys, request/receipt/payload digests, foreign references, operation transitions, complete committed group membership, unique trusted capture-session ownership and every retraction/barrier cause. Derive current projections from validated operation evidence and compare them with exported state; refuse contradictory active/tombstoned claims rather than pick an order from filenames or timestamps. Preserve inherited issuer/restore rules: old receipts remain immutable history; no old issuer grants runtime authority in the destination.

Restore atomically installs validated lifecycle evidence with inherited source/history authorities, rebuilds its checked SQLite projections and starts without vector state or enabled local inference. Old supported Portable inputs seed no session/retraction/import facts and retain their historical coordinate meaning. Portable12 and older readers refuse Portable13 before mutation; they must not fall back to parsing its inherited subset. Test export/restore/re-export equality of immutable evidence, tombstone exclusion and receipt replay without recapture or renewed session membership.
