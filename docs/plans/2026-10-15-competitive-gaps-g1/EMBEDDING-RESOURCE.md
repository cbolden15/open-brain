Date: 2026-10-15. Status: proposed contract frozen for implementation review; no helper, model installation, vector cache or semantic retrieval is implemented by this document. Baseline: `8ef1d069259c291e669341079806103c8fa90e86`, schema/runtime/Portable **17/12/12**. New persistence coordinates are allocated only by the coordinator's reviewed compatibility migration. This specification does not allocate or infer them.

The shared `PERSISTENCE.md` in this directory specifies the lifecycle authority and reserves18/13/13 for its implementation. Existing constants remain17/12/12. Its shared eligibility generation, disabled-on-restore local embedding consent and public error mapping apply here; concrete DDL/evidence schemas still require implementation review. Component manifest v2 and derived cache v1 are separate version axes, not replacements for engine compatibility.

The proper product is a pinned CPU helper, tokenizer and model installed with the normal Homebrew resource set. The app still depends exactly on `open-brain-engine==0.1.0`; no ML package enters the audited Python core. The engine owns authorization, projection, revisions, cache identity, retrieval and final output. A helper is an untrusted computation boundary and receives no authority. Installation is automatic with the selected candidate; local text processing requires explicit current owner embedding consent. Existing provider egress consent remains separate.

## 3. Component manifest v2 and installation

Retain the v1 filename, header, accepted role sets, ordering, field validation and renderer output for legacy input unchanged. Never append an embedding line or an inventory field to v1. Introduce a separately dispatched canonical UTF-8 JSON document named `open-brain-component-manifest-v2.json`, schema `open-brain.component-manifest.v2`. Its parser rejects duplicate keys, unknown fields, noncanonical bytes and unknown role/platform/schema values. A v2 manifest requires exactly both supported platforms and equal role sets: `{base,graphify,embedding}` or `{base,graphify,harness,embedding}`. It is not an optional silent v1 extension.

| Object/field | Frozen v2 requirement |
|---|---|
| Root | Exactly `schema`, `version`, `resources`; `schema` fixed above, release version obeys current version grammar, resources sorted by platform then `base,graphify,harness,embedding`. |
| Each resource | Exactly `role`, `platform`, `filename`, `archive_sha256`, `archive_bytes`, `executable`, `executable_sha256`, `inventory`, `inventory_sha256`; lowercase 64-hex hashes, positive integer byte counts (booleans refused), distinct roles/files per platform. |
| `platform` | `linux-x86_64` or `macos-arm64`; platform and release version must agree with the filename. No architecture translation. |
| `filename` | `open-brain-components-v2-{role}-{version}-{platform}.tar.gz` for every role; a new filename namespace prevents a v1 reader mistaking changed archive layouts for old artifacts. No arbitrary URL, whitespace, slash or path traversal. Release origin remains separately validated by the renderer. |
| `executable` | Fixed relative installed path: existing base/Graphify/harness destinations; embedding is `libexec/open-brain-embedding/open-brain-embedding`. No role-supplied arbitrary executable. |
| `inventory` | Fixed installed `share/open-brain/inventories/{role}.json`; inventory hash is external to the archive's own inventory. It inventories every archive member except its own bytes. Base and legacy resources need new v2 inventories too; no fabricated inherited hash. |

Inventory schema `open-brain.resource-inventory.v1` has exactly `schema`, `release_version`, `role`, `platform`, `members`, `component`. Members are sorted unique relative POSIX paths, with exact objects `{path,kind,mode,bytes,sha256}`: regular files only plus directories with `bytes:0,sha256:null`; permitted modes `0644/0755` for files and `0755` directories. Reject absolute/empty/dot/dot-dot/backslash/NUL paths, links/hardlinks, duplicate members, devices, FIFOs, sparse files, extra undeclared files and collisions. No executable bit on model/config/legal assets. Embedding permits at most 256 members, 32 MiB compressed archive overhead above payload budget, 250 MiB total installed bytes and 160 MiB per file; the two existing FP32 assets fit individual limits, which does not prove the full resource fits. Extraction streams with these bounds before writing and refuses expansion exceeding declared inventory or totals.

All v2 archives use final installed prefix-relative paths, so inventory paths name the same bytes at extraction and runtime; v2 rendering does not reuse v1 rename/stage rules. Each role has a fixed disjoint allowed path set including its executable, assets, role notices and its inventory; shared directories may repeat only as identical directory entries. Nonembedding inventories have `component:null`; their executable/member hashes still bind them. The inventory itself is excluded from `members` to avoid self-hashing and is checked against the outer manifest's `inventory_sha256`. The whole archive hash binds every member including the inventory.

**Amendment 2026-10-17 (T5.1 one-folder base, owner ruling D17/D14 option a).** The base is now a PyInstaller one-folder build, because the one-file base waited about 10 s on a fresh extraction for every macOS command. Inventory v1 therefore admits contained relative symlink members for the base and harness roles only. A link member is exactly `{path,kind:"symlink",mode:511,bytes:0,sha256:null,target}`; every other member keeps the five-field object, so existing inventories (including the embedding inventory) are byte-identical. The target is a non-empty relative POSIX path with no NUL, backslash, `.` or empty component, and `..` only as a leading run. It is resolved lexically from the link's parent, following link prefixes at most four hops with cycles refused, and must end on a declared regular file or directory below the role root (`libexec/open-brain/` for base, `libexec/open-brain-harness/` for harness). Link members live below that root, except the base entry link `bin/open-brain` → `../libexec/open-brain/open-brain`. Every parent of every member is a declared real directory, so no member is reached through a link. The base executable is `libexec/open-brain/open-brain`. Graphify and embedding inventories stay link-free. Extraction creates links without following them and verification compares `readlink` targets without following them.

For embedding, `component` has exactly `protocol`, `helper_build`, `runtime_build`, `model`, `preprocess`, `notices_sha256`:

| Field | Bound identity |
|---|---|
| `protocol` | `open-brain.embedding-helper.v1` |
| `helper_build` | Product source commit, reproducible build recipe SHA-256, executable SHA-256, target triple, minimum OS/CPU feature list and dependency lock SHA-256. Concrete values are release gates, not placeholders accepted by parser. |
| `runtime_build` | Exact upstream commit, build recipe/digest, `cpu_only:true`, `telemetry_compiled:false`, complete dependency/license inventory hash; no dynamically discoverable execution providers/custom operators. |
| `model` | Repository/revision, fixed inventory path, byte length and SHA-256 of graph and any explicitly allowed external data. Proposed first profile requires one self-contained ONNX graph; external locations and executable model code are refused. |
| `preprocess` | Profile ID, exact tokenizer/config/vocabulary hashes, tokenizer implementation/build identity, segmenter version, dimensions, pooling, normalization, special token IDs, sequence/window/overlap and purpose-prefix rules. |
| `notices_sha256` | Full model/tokenizer/runtime/transitive LICENSE and NOTICE inventory; a model-card license label alone cannot satisfy it. |

`component_id` is SHA-256 of canonical `component` JSON, excluding no fields; full installed resource integrity also binds the inventory. Changes to weights, pooling, tokenizer, runtime build, CPU kernels or helper create a new identity. No cross-release cache reuse on a merely equal model name.

Cross-check duplicate declarations: helper-build executable hash equals the outer resource executable hash; model/tokenizer/runtime path, byte counts and hashes equal their inventory entries; release/platform agree at every layer. Embedding paths are fixed below `libexec/open-brain-embedding/`: executable `open-brain-embedding`, graph `model/model.onnx`, tokenizer/config/vocab under `tokenizer/`, and exact pinned native library names under `runtime/`. Notices live below `share/open-brain/licenses/embedding/`; no other installed payload prefix is allowed. Any extra native library or new model external-data file requires a separately reviewed component/inventory contract.

The formula stages into a new immutable versioned keg, verifies archive/inventory/member/executable hashes, installs notices and the manifest, and runs a metadata-only identity check. Activation occurs only after the entire candidate set verifies. Interrupted install leaves the previous complete keg selected; never mix an old base and new embedding tree. Unsupported v2/candidate compatibility is refused by packaging/launcher selection **before Brain bootstrap**. v1 remains installable as the legacy lexical surface. Rollback selects a whole verified resource set and separately obeys Brain compatibility: it never points an older engine at upgraded authoritative state.

## 4. Runtime trust and execution

Resolve only from the real versioned prefix of the currently running installed base, using the fixed manifest paths. Resolve the initial Homebrew bin symlink once to that prefix; after this point reject symlinks in resource/inventory paths and mutable prefix switching. **Amendment 2026-10-17 (T5.1):** the resolved base executable is `<prefix>/libexec/open-brain/open-brain` (PyInstaller reports the resolved executable as `sys.executable` when launched through `bin/open-brain`), and one shared rule maps it to the prefix; the one-file `<prefix>/bin/open-brain` layout stays accepted only for the contributor desktop runtime. No PATH search, environment override, user model path, shell, registry, ambient cache, credentials, remote URL, generic ONNX executable or automatic repair/download. Contributor tests inject a typed backend; source execution without an approved resource returns unavailable.

Trust roots are the release-pinned base/manifest hashes selected through the verified installation and normal host/package trust. A neighboring manifest that an attacker can rewrite along with all files is not a signature or independent trust root. The product does not defend against a hostile same-UID process, administrator or compromised host; no kernel sandbox or cryptographic publisher authenticity is claimed here.

Before text release, verify the selected manifest/inventory against the base's approved component identity, open resources relative to a held prefix directory descriptor with no-follow semantics, and verify regular-file ownership/permissions/link count, size and SHA-256 through those descriptors. Reject writable-by-group/other parents or files. Detect stat identity/size/time changes across reads. **Amendment 2026-10-17 (G4 Homebrew smoke, D15):** inside the installed prefix this rule stands unchanged; ancestors above the prefix share the base executable's trust (Homebrew's `Cellar` is group-writable `0775` by design), so a group-writable ancestor is admitted when it is owned by root or the current user, while other-writable ancestors still require the sticky bit. Integrity rests on descriptor-held hashing and the private stage, not on ancestor modes. Executing a path after hashing it is insufficient.

The portable implementation contract uses a private per-invocation staging directory (`0700`) created beneath the already admitted local state/cache root without following links. Copy only verified open-descriptor bytes using exclusive no-follow creation, hash staged bytes, close writable descriptors, set executable/native libraries `0500` and read-only model/config `0400`, and execute the staged absolute binary with only staged absolute library/model resolution. Recheck staged descriptor identities before launch. Never accept a resource path from JSON. Keep staging alive until the child is reaped; remove it after failure/success with no symlink traversal. A different implementation must prove execution/loading of the same verified bytes on both platforms; if that cannot be shown, refuse. Private staging is race containment within the host trust boundary, not isolation from malicious same-user code. Its copy cost and temporary disk use are measured acceptance gates.

**Amendment 2026-10-17 (G4 spike evidence; supersedes the per-invocation copy and removal above).** On macOS arm64 the first execution of freshly written helper and runtime bytes costs about 600 ms of system code validation and freshly written model data about 320 ms more, so per-invocation copies made every query cost about 700 ms (warm p95 1213 ms against the 500 ms budget). The stage is therefore persistent per component: `.open-brain/cache/embedding-v1/stage/<component_id>/` below the admitted Brain root, private `0700` directories, executable/library `0500`, data `0400`, regular single-link files owned by the current user, created from verified installed bytes with exclusive no-follow creation. Before **every** launch the parent reopens each staged file no-follow, checks owner, mode, link count, size and stat identity, and hashes all bytes against the installed inventory; any mismatch removes and recreates the stage and that launch does not use it. Measured per-query cost with the full re-hash: p95 171 ms. The equivalence argument and rejected options are in the goal decision record D7. The stage is derived cache: excluded from Portable, deletable without data loss, and counted in cache disk accounting.

Run one unprivileged foreground child per bounded exchange with fixed argv `--stdio-v1`, inherited private stdin/stdout pipes, `cwd` equal to its staging directory and `close_fds` except standard streams. No Brain path, database, open engine descriptor, provider credential, home/config path or user environment is inherited. Allowlisted environment is only fixed locale, deterministic thread settings and `ORT_DISABLE_TELEMETRY=1` as defense in depth; telemetry must already be absent from the native build. GPU, provider plugins, Hub clients, logging, profiling, session serialization, subprocess creation and network transports are omitted. Native loader dependency resolution must be fixed to the audited staged/system allowlist, never ambient loader variables. No listener or resident worker survives the owning command.

Only one child per Brain foreground embedding operation and at most two CPU execution threads. CPU feature mismatch fails before text release. Continuous nonblocking stdout/stderr draining enforces byte caps while the child runs; checking output size after unbounded `communicate` or disk output is insufficient. Discard stderr without exposing text and stop if it exceeds its cap. No per-text diagnostic, query hash, vector, model path, panic/backtrace or native error string enters logs/receipts.

## 5. Exact helper protocol v1

One strict UTF-8 JSON object followed by one LF, then EOF, per process. No streaming conversational session. Reject BOM, invalid UTF-8, duplicate keys, unknown fields, nonfinite numbers, nested depth above 8, extra frames or trailing bytes. Request and response IDs are opaque caller-generated 32 lowercase hex characters, not record/capture IDs. JSON numeric integers exclude booleans. Hashes are 64 lowercase hex strings. Helper identity/capabilities are checked using a separate **text-free** invocation before the text-bearing one. Every response repeats protocol/request/component bindings; response self-report supplements byte verification and never replaces it.

| Request | Exact keys and values |
|---|---|
| `capabilities` | `{protocol,request_id,operation}`; protocol fixed; operation `capabilities`. |
| `embed` | `{protocol,request_id,operation,component_id,purpose,items}`; operation `embed`; purpose `query` or `document`; items array of exact `{slot,text}` objects, slots contiguous integers from zero, text NFC valid Unicode without surrogate code points. No path, identity, consent, scope or arbitrary option fields. |

Capabilities success has exactly `{protocol,request_id,status,component_id,limits}` with `status:"ok"`. `limits` has exactly the following integer fields and values, all compared for equality to the approved protocol, not negotiated upwards:

| Limit | Value |
|---|---:|
| `max_request_bytes` / `max_response_bytes` / `max_stderr_bytes` | 131072 / 1048576 / 4096 |
| `max_items` / `max_total_chunks` / `max_document_bytes` / `max_query_bytes` | 4 / 128 / 65536 / 8192 |
| `dimensions` / `max_query_tokens` / `document_window_tokens` / `document_overlap_tokens` | 384 / 254 / 224 / 32 |
| `capabilities_deadline_ms` / `query_deadline_ms` / `document_deadline_ms` | 2000 / 10000 / 60000 |

Request byte cap includes framing/escaping and is checked by caller and child; per-item limits do not override total limits. Query purpose requires exactly one nonblank item and one vector; document purpose permits 1–4 nonblank items and at most 128 chunks across them. A long query, document or batch fails whole with `input_limit`; no silent prefix embedding, truncation or partial vectors. A rebuild is multiple bounded exchanges with a parent 600-second budget, cancellable between and during exchanges. These are proposed helper safety ceilings, not changes to existing production deadlines or claimed response latencies.

Embed success has exactly `{protocol,request_id,status,component_id,purpose,items}`. Each item is exactly `{slot,text_sha256,token_count,chunks}`; hash covers exact UTF-8 input, and `token_count` counts content tokens before special tokens. Each chunk is exactly `{ordinal,token_start,token_end,byte_start,byte_end,vector}` with half-open ranges, consecutive ordinals, valid UTF-8 byte boundaries, and vector length 384. Query has one chunk covering all content tokens; document ranges follow the frozen window algorithm. A mismatched/missing/duplicate/extra slot, unexpected chunk, invalid range/hash or excessive output invalidates the entire exchange.

Every error response has exactly `{protocol,request_id,status,error}` with `status:"error"` and error exactly `{code,retryable}`. Child codes are `protocol_unsupported`, `request_invalid`, `component_mismatch`, `input_limit`, `tokenization_failed`, `inference_failed`; `retryable:false` for all v1 child codes. An unreadable request uses all-zero request ID; caller never mistakes it for success. Successful framed responses exit zero; framed errors exit 2. Other exits/signals, zero-without-frame or error frame with zero exit are worker failure. Native details never cross the boundary.

Illustrative valid request (IDs are synthetic):

```json
{"protocol":"open-brain.embedding-helper.v1","request_id":"0123456789abcdef0123456789abcdef","operation":"embed","component_id":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","purpose":"query","items":[{"slot":0,"text":"Where did we discuss local memory?"}]}
```

Illustrative bounded error:

```json
{"protocol":"open-brain.embedding-helper.v1","request_id":"0123456789abcdef0123456789abcdef","status":"error","error":{"code":"input_limit","retryable":false}}
```

The parent owns monotonic deadlines starting before resource verification/staging, not only inference. On cancellation/deadline/output overflow, close stdin, stop accepting output, terminate the child, wait at most 500 ms, then kill/reap with another 500 ms ceiling. A cleanup failure fails the operation and prevents any cache publication. No retry loop, provider fallback, background continuation or half-success response. Parent failure categories use `ob.embedding-error.v1`: `consent_required`, `resource_missing`, `resource_untrusted`, `component_mismatch`, `unsupported_platform`, `input_limit`, `protocol_invalid`, `worker_failed`, `deadline`, `cancelled`, `cleanup_failed`, `cache_invalid`, `cache_incomplete`, `currentness_changed`. Retryability is an owner-visible hint only (`currentness_changed`, `cache_incomplete`, `deadline` may be retried by a fresh explicit operation); never automatic text replay.

## 6. Preprocessing, segmentation and numeric validation

First profile is proposed `ob.minilm-wordpiece-mean.v1`, bound to the exact MiniLM tokenizer/config/vocab above. Use only the engine-authorized projected string; normalize NFC once in engine and hash those bytes. No title/body mixing, invented summary, Markdown evaluation, URL fetch, added instruction or Unicode compatibility folding. Treat title and body as separate derived items, tagged only in engine. Helper uses pinned tokenizer normalizer/pretokenizer/special-token rules with truncation disabled; tokenizer lowercasing belongs to its pinned profile, not an extra engine transformation.

Tokenize each complete bounded item without special tokens. For documents, window token indices `[0,min(224,N))`, then advance 192 tokens until the previous end equals N; no redundant trailing overlap-only window. Add the profile's CLS/SEP tokens to each window, pad within a batch with attention masks and exclude padding from masked mean pooling. Token windows use original token IDs, not independently retokenized partial-word substrings. Offset ranges are minimal original UTF-8 byte spans covering the selected tokens; overlaps are intentional, and tokenizer fixtures must account for whitespace, punctuation, unknown tokens, composed/decomposed accents, emoji and long single words. All non-whitespace text must be represented or the item fails `tokenization_failed`. Empty-token results fail. Engine verifies offset/range/order/coverage invariants and derives chunk identity itself; the trusted pinned implementation plus golden fixtures proves tokenization, not a helper-supplied identity.

For queries, tokenize once, reject above 254 content tokens and add CLS/SEP. The MiniLM 256 total ceiling therefore remains respected. Masked mean pool exactly the selected model's last hidden state, then L2 normalize. Helper graph output names/shapes/types and special-token pooling parity must be verified against the actual pinned ONNX graph before profile approval. Model metadata alone does not prove that graph returns raw token states rather than an already pooled output. BGE requires a distinct profile with CLS pooling and separately frozen query-prefix rules; it cannot use this profile ID.

Parent rejects wrong dimension, booleans, NaN/Infinity, nonnumeric entries, subnormal/overflow conversion problems, zero norm, components outside `[-1.0001,1.0001]` or norm outside `[0.999,1.001]`. Canonical stored representation is IEEE754 float32 little endian, exactly 1536 bytes per vector. Recheck finiteness/norm after conversion; canonicalize negative zero. Parent computes cosine/dot scoring in deterministic float64 accumulation order on normalized float32 values; it never accepts helper scores, result IDs, trust or ranking. Cross-CPU low-bit differences are not promised bit-identical: numeric tolerances and quality stability are gates, and a runtime/kernel identity change starts a new generation.

## 7. Authorization and currentness before text, cache and output

The engine creates the sole currentness token `ob.embedding-currentness.v1`. It is internal, never sent to the helper or a client. Canonical JSON uses exact required fields; nullable relationships use JSON null, never omitted, empty string or hash-of-empty as a substitute. Empty existing member lists hash canonical `[]`; absent/nonapplicable relationships are null. Invalid/missing required evidence refuses eligibility.

| Token field | Engine-owned meaning |
|---|---|
| `schema`, `brain_id`, `issuer_epoch` | Fixed token namespace and current admitted Brain/issuer identity. |
| `authorization_generation`, `authority_binding_sha256` | Current authority generation and SHA-256 of existing `paging.authority_binding(authority)` canonical object. Includes principal/session/capabilities/scopes/tiers/egress/provider/consent; never helper claims. |
| `authorized_retrieval_sha256` | Digest of eligible authority-visible records/current dependencies, extending existing authorized retrieval digest with tombstone/import activation eligibility. It must not include unauthorized row content. |
| `eligibility_generation` | Coordinator-owned monotone authoritative transaction generation advanced atomically on activation/retraction and other eligibility changes. Internal race fence; scoped public cursors use the authority-visible digest, not an unrelated global-change oracle. |
| `record_type`, `record_id`, `revision_id`, `projection_sha256` | Exact engine result/revision and normalized projected item bytes/field kind; no capture/source identity from helper. |
| `logical_source_preimage_sha256` | Hash of exact source ID/head/head-version/route-version/space/lifecycle/availability/history/tombstone state when applicable; null for a canonical record. |
| `canonical_members_sha256` | Hash of ordered current publication/member revisions and their effective privacy/lifecycle/tombstone/dependency preimages for canonical records; null for source records. Empty/ambiguous canonical member sets are ineligible. |
| `import_receipt_binding_sha256` | Engine hash of active complete conversation-revision/segment receipt binding, or ordered member bindings for canonical records; null for non-import records. Unactivated or retracted import groups cannot provide a token. |
| `embedding_policy_generation` | Current explicit local embedding consent/policy generation; permission must cover selected view and processing purpose before any text is released. Revocation changes it atomically. |

Authorized snapshot flow:

1. Under the ordinary engine read admission/snapshot, require the existing surface grant and current local embedding consent. Intersect owner opt-in tiers with effective authority, source lifecycle, tombstones, import activation, canonical member validity and current privacy. Owner-local processing may use its eligible owner view only under that opt-in. Nonowner/provider callers get exactly their authority-visible/redacted projection; owner vectors never enrich a restricted view. Query text itself obeys the same consent gate.
2. Collect bounded immutable projected items and tokens. End the snapshot/lease before spawning a child. Do not hold a writer lease, read snapshot or owner prompt over helper execution. Run bounded inference outside engine locks.
3. Reacquire engine read admission and resolve fresh authority, consent and every token preimage. Any changed identity/revision/projection/dependency/policy or authority-visible eligibility discards all results from the exchange with `currentness_changed`. A changed global `eligibility_generation` requires complete revalidation: a scoped result may rebase that internal fence only after proving every authorized visible preimage and digest unchanged, without replaying text or accepting helper authority. This prevents unrelated unauthorized mutations becoming an observable cursor/error generation oracle; constant-time execution is not claimed. No inference result can resurrect a retired revision. A session append invalidates a session-bound token through its engine dependency digest.
4. Publish a cache generation only after all coverage/preimage checks succeed, with atomic cache-directory swap under a shared engine eligibility/admission fence that excludes authoritative mutation for the short final check-and-swap. No child runs under that fence. If the implementation cannot compose the cache filesystem operation with this fence, it must refuse publication; a pre-swap check alone is insufficient. Queries still revalidate rather than trusting publication.
5. For each query, authorize and filter before reading vectors into scoring, fuse and limit only authorized records, and resolve the current `RecordProjector` again before materializing output. Revalidate all query/cache/token bindings within the final read admission; serialize the bounded response there. Return an internal immutable output envelope containing token/binding digest to the shared transport, which performs a final admission/generation check immediately before first-byte handoff and holds the shared read fence through that bounded write. If delayed/queued, rebuild the envelope or refuse; no helper text or stale buffered response escapes after an observed revocation. Bytes already handed to a client cannot be recalled; transport handoff is the documented linearization boundary.

The fenced transport write uses nonblocking bounded framing, existing response-size limits and at most a 1000 ms monotonic handoff deadline. Client backpressure/cancellation closes the response and releases admission; it never holds the engine fence over an unbounded flush, client acknowledgment or deferred event queue. A partial already-handed-off frame cannot be recalled and is treated as a transport failure, never a successful search receipt.

No helper statement or cache row grants eligibility. Search grant does not grant local embedding policy, content-read/history-read or provider egress. Cloud consent is never inferred from local opt-in. A permission failure is surfaced as an ordinary permission failure, not disguised by semantic fallback.

## 8. Derived cache, ranking and cursor contract

Namespace `ob.embedding-cache.v1`; stored only below admitted Brain-local `.open-brain/cache/embedding-v1/`, private `0700` directories/`0600` files with no links. No modification of authoritative SQLite or migration is implied. Older engines ignore this isolated derived directory; they must not read or repair it. It is not Portable content, source evidence, an import receipt, or a way to reopen an incompatible Brain.

| Record | Required binding |
|---|---|
| Generation manifest | Schema, unique random generation ID, component/inventory IDs, preprocess/segmenter IDs, engine projection version, view key, eligibility snapshot digest, expected complete record/chunk counts, sorted member digest, vector-file digests, `state:"complete"`. Manifest is written last, fsynced with files and parent before activation. |
| View key | Domain-separated SHA-256 of exact authority projection class, Brain/issuer, scope, tiers, egress/provider/consent and embedding policy; initial implementation uses full authority binding for conservative separation. | Chunk key | Domain-separated canonical hash of component/preprocess/segmenter/view, record/revision/field identity, projection hash, token/byte ranges and relevant engine token preimages. Engine derives it after validating helper output. |

Write new generations into unique staging directories. Keep previous complete generation until new complete coverage verifies; crash/cancel/disk-full/helper failure leaves it intact. Partial generations are never selected. Acquire one derivation lock per view, refuse competing builds, retain no query vectors across commands, and remove abandoned temporary files only after custody checks. Bounded quotas: 100,000 chunks, 512 MiB per view and 1 GiB total embedding cache including staging; preflight and streaming accounting include both old/new generations. Larger input returns `cache_incomplete`/explicit capacity status, never silently indexes a prefix. Ten-thousand-chunk acceptance is below this ceiling; the ceiling is not a performance claim.

Model/policy/projection change creates a fresh generation. A previous complete generation may be reused only when every selected item's exact current preimages and full required eligible coverage still match; otherwise `hybrid_required` refuses `model_unavailable` and optional mode returns an explicit lexical fallback warning. Retraction/privacy/route/edit invalidation takes effect at authoritative commit even if cache garbage collection lags. Deleting the cache loses no records. Restore validates its normal Portable evidence, starts with no vectors and requires explicit bounded foreground rebuild under current consent. Backups and history may retain old material; no secure erasure claim is made.

Initial ranking is exact scan over eligible current vectors only, no ANN overfetch. Collapse chunks to each record's maximum cosine, deterministic tie by record type/result ID. Combine semantic and existing lexical lists by `ob.hybrid-rrf.v1`: equal weights, reciprocal ranks `1/(60+rank)` with ranks starting at 1, missing list contributes zero; no query-specific tuning. Sort fused score descending, then record type/result ID binary. Apply result/byte limits only after fusion and record collapse; retain existing 240,000-byte search payload bound. Frozen quality tests must validate this proposal before shipping; changing constants requires ranking ID change and new evidence.

**Amendment 2026-10-17 (G4 spike evidence): ranking is `ob.hybrid-rrf.v2`.** On the frozen synthetic corpus with the engine's own `fts5-match-tier-binary-v2` lexical ranking, v1 scored paraphrase hit@5 20% while semantic alone scored 100%: lexical tier 5 (the any-term disjunction) is ordered only by record type and result ID, so its positions carry no relevance and reciprocal-rank fusion rewards arbitrary identifiers. v2 is v1 with one change: the lexical input list contains only lexical tiers 1–4 (title phrase, title all terms, phrase, all terms). Records matching only tier 5 still reach hybrid results through the semantic list. Measured v2: paraphrase hit@5 100%, exact-ID hit@5 100%, zero exact-ID regressions (MiniLM). Lexical-only mode and `fts5-match-tier-binary-v2` are unchanged. Decision record D5. As in that evidence, each input list is cut at its first 50 records (semantic: the 50 best caller-visible records by maximum cosine; lexical: the first 50 tier 1–4 rows), so a hybrid result set holds at most 100 records and pagination walks that set (decision record D13).

Cursors remain engine-owned opaque `CursorStore` entries, never helper IDs. Bind request/filter/mode/limit, existing authority binding and visible generation, component/preprocess/segmenter/projection/fusion IDs, view key, complete cache generation and last exact score/result/revision key. Refuse lexical-to-hybrid continuation and `hybrid_preferred` fallback on an existing hybrid cursor: return `cursor_stale` and require a new first page. Scoped cursor staleness must depend on authorized visible state; internal global eligibility changes trigger revalidation, not an unauthorized-change signal by themselves. Model rebuild/identity change stales all affected hybrid cursors. No new cursor wire format or relaxation of frozen DTO v1 is silently introduced.

Shared CLI/MCP/plugin/desktop/harness behavior: `lexical` never runs a helper; `hybrid_required` returns no lexical success on unavailable/corrupt/incomplete resource/cache; fresh `hybrid_preferred` may return `mode_used:"lexical"` with existing `model_unavailable` warning. Successful semantic responses use existing `mode_used:"hybrid"`, already admitted by `packages/engine/src/open_brain_engine/engine/t03_schema.json`; do not extend frozen DTO v1 merely for this value. Coordinator owns exact public error mapping and any separately reviewed extension needed for new errors. Detailed resource failures stay owner-local health categories; external clients get bounded existing permission/model/cursor errors without filesystem/component/cache statistics.
