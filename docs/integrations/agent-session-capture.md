# Agent session capture

Open Brain can capture fresh sessions from an explicitly selected project running Claude
Code or Codex. Capture is off until the project has an enabled choice for each content
type. `session_summary` and `session_transcript` are separate choices. A summary is
extractive and starts with `Extractive session summary:`. It is never generated by a
model.

The session source is local-only. It uses `account:local:claude_code` or
`account:local:codex` so session identifiers from the two clients cannot share a source
identity. The project identifier is a SHA-256-derived `project:<hex>` value from the
canonical selected project path.

## Project-local hook setup

Use `AgentSessionHookManager` with the collector's private state root. It has a
preimage-bound lifecycle:

1. Call `preview_apply(client, project_path)` and show the returned configuration path
   and `changed` value.
2. Call `apply(preview)` only if the saved configuration still has the previewed digest.
3. To remove capture, call `preview_uninstall(client, project_path)`, then
   `uninstall(preview)`.

Claude Code receives one owned synchronous, two-second-bounded `Stop` command in the
selected project's `.claude/settings.local.json`. This is deliberate: Claude print mode
can exit before a background Stop command writes its receipt. Codex receives one owned
asynchronous `Stop` command in the selected project's `.codex/hooks.json`. Existing
hooks and other settings remain in place. These are project-local files only; the
integration never changes `~/.claude` or `~/.codex` configuration.

The installed command is equivalent to:

```text
python -m open_brain_connectors.runtime.agent_session_hooks enqueue \
  --root <private-state-root> --client <claude_code|codex> \
  --project <selected-project> --owner open-brain-agent-session
```

It reads the lifecycle JSON from standard input and always exits successfully. A capture
failure therefore cannot delay or fail the client turn.

## Queue and parsing

The hook writes a bounded, owner-only queue entry under
`<private-state-root>/agent-session-queue`. Entries contain project, client, session,
hook event, transcript path, and observed transcript modification time. They do not
contain transcript text. The source reads only a transcript named by a fresh queued
event. It does not discover old client history.

The queue holds 256 events. After each durable collector apply and checkpoint commit,
call `AgentSessionLiveSource.acknowledge(selection, checkpoint)`. It removes only the
captured event and older observations of that same client/project/session. Calling it
again before the next fetch is safe recovery. It never deletes a newer event or another
project's event. This keeps automatic collection running beyond 256 events without a
manual discard. If a queue still reaches capacity, the hook records a metadata-only
dropped-event counter and later fetches report `session_queue_full`; it never blocks the
client.

`AgentSessionLiveSource.fetch(selection, options, checkpoint)` requires exactly these
options:

```json
{
  "client": "claude_code",
  "project_path": "/absolute/selected/project",
  "capture_summary": false,
  "capture_transcript": true
}
```

The selection must use `connector_name: "agent_session"`, resource type `local_project`,
the canonical project ID, and the client-specific local account ID. The proposed
checkpoint contains at most 256 `captured_event_ids` plus the canonical `project_path`;
fetch never writes it or consumes queue entries. It first groups all queue events by
session, chooses the newest observation, and only then applies the checkpoint. An older
Stop event therefore cannot return after the newest one was captured. Quarantined entries
can still be explicitly removed with:

```text
python -m open_brain_connectors.runtime.agent_session_hooks discard \
  --root <private-state-root> --event-id <32-lowercase-hex-id>
```

Current adapters accept the documented Claude Code JSONL message records and Codex
`response_item` message records. Claude records must bind `sessionId` and `cwd` to the
queued event and selected project. Codex must include a matching `session_meta` payload
with `id` and `cwd`. The transcript device and inode must also match the hook observation.
Tool calls, tool results, thinking or reasoning blocks, and unrecognized record shapes
are excluded. A trailing partial JSONL line is tolerated. Metadata mismatch or a path
swap fails closed with a stable session notice.

Before any extracted text enters an intake, Open Brain rejects supported credential
patterns, private-key headers, and credential URLs. The event remains queued and fetch
returns the metadata-only `session_quarantined_secret` notice; use `discard` after review.
This scan is best effort. It cannot find every secret embedded in ordinary prose.

## Client evidence and limits

The tested client versions are Claude Code 2.1.271 and Codex CLI 0.154.0. Claude Code
documents `Stop` as running after the main agent responds and supplies `session_id`,
`cwd`, `transcript_path`, and the event name to command hooks. Codex documents `Stop`,
project-local `.codex/hooks.json`, the same core path/session fields, and warns that its
transcript wire format is not a stable hook interface.

References checked on 2026-09-15:

- [Claude Code hooks](https://code.claude.com/docs/en/hooks)
- [Codex hooks](https://developers.openai.com/codex/hooks/)

Synthetic transcript tests prove the supported shapes and hook configuration behavior.
They are not live client acceptance evidence. A final owner-run proof needs a fresh test
project for each client, one enabled content choice, one completed turn, a collector
drain, a restart, and explicit uninstall/opt-out confirmation.
