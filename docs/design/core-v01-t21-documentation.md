## Bounded documentation and executable gate

README, CLI reference, agent setup, first-use, source guides, doctor and the feature/version matrix
must describe actual candidate commands without promoting source-only/developer-accepted features
to public readiness. Historical provider and desktop instructions remain labeled historical or
contributor-only. Deferred T10–T18/T22 and existing Obsidian/desktop boundaries remain unchanged.

The canonical first-use and doctor guides contain marked runnable blocks. The documentation
harness executes their exact text with synthetic fixtures and response-derived IDs, not a second
implementation of the example. It must cover capture plus Markdown import, routing both sources,
proposal creation, inspection, approval, canonical vault bytes, source/canonical search, complete
Unicode reads with continuation, all doctor checks, and both clients' synthetic setup/removal and
actual MCP catalog/grant discovery. Packaged Obsidian staging/status/removal is CLI evidence only.
Reference templates identify their placeholders and link to these executable examples.

Run against exact hash-verified T20 archive resources staged in a clean installed prefix. Child
processes use clean temporary HOME/data/cwd and no PYTHONPATH or developer checkout imports.
No live sources, ambient credentials, real services or model downloads are required. Raw logs,
configuration, prompts, reviews and usage stay private; public evidence is bounded counts/hashes.

Focused regression checks must detect changed/missing blocks, invalid commands and incomplete or
incorrect results. A passing shell exit is insufficient: require observed block completion in order
and validated required operations (including all four doctor calls). Generated agent configurations
must actually launch and expose the exact intended nine-grant tool set, with successful protocol
responses and matching catalog authorization. Bind the three README MCP JSON configurations to the
executed grant cases, and compare feature-table values by named coordinate. Mutation tests must
reject early success, skipped doctor checks, narrowed/widened grants and reference drift. The coordinator runs the frozen executable gate, independent strong-model review
and any repair delta, serial `make -j1 verify`, `git diff --check`, and
`actionlint .github/workflows/ci.yml`. One heavy build runs at a time.

The separate artifact gate is `uv run --frozen python -m tools.open_brain_dev.documentation_examples`.
Its required options are `--artifact` (absolute installed executable), `--root` (absolute checkout
containing the guides), and `--output` (absolute private JSON receipt). The runner uses the checkout
only to read documentation; it stages the candidate and runs product commands outside it. The
T21 gate pins the verified local macOS artifact and resource digests; it is not Linux or arbitrary
future-artifact acceptance. `make verify` runs the supporting regression tests, not this separately
invoked artifact gate.
