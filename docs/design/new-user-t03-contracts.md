## 3. Identity, ordering, route and evidence invariants

A logical source has an opaque `source_id` bound to `(connector_name, connection_id, resource_id, external_id)`. Do not expose this private tuple, its raw digest or operational paths in public results. Manual captures each receive independent logical identity. Equal URLs/text are not merge authority. Revision identity is `(source_id, upstream_revision_key)` and maps once to an immutable `capture_id`; retain existing capture IDs. Canonical `page_id` is stable, with immutable page `revision_id` and exact source revision members. Legacy `PublicProvenance.source_record_id` means a capture ID; do not repurpose it as logical-source ID.

A proposed ingestion submission contains `dto_version`, namespaced identity, upstream revision key, exact canonical submission digest, payload, expected head capture ID (nullable for creation), ordering evidence, and expected collector control epoch. Digest covers payload **and metadata**, including title/provenance/privacy. A replay with equal key/digest returns the original receipt; equal key/different digest returns `source_revision_conflict`. Metadata-only updates require a new revision key. Preserve preexisting delivery aliases with an explicit mapping; do not regenerate them from new IDs.

Ordering evidence is a tagged union: `predecessor` with exact prior revision key, `monotonic` with provider namespace/order epoch/integer sequence, or `unordered`. Reject incomparable epochs and fabricated predecessor chains. Wall-clock timestamps and lexical token sorting never establish upstream order. Head promotion requires expected-head CAS and validated newer/predecessor evidence under the writer lease. A late revision can enter immutable history with `history_only`; unordered divergence is quarantined until explicit owner resolution. Neither may roll back head. Revalidate control epoch before commit.

Source route is `{source_id, space_id, route_version}`; changes require expected route version and head. Routing follows later heads, without changing capture bytes, source authorship or trust. Source lifecycle (`active`, `retired`, reserved-for-forget) and availability (`available`, `missing`, `inaccessible`, `unknown`) are separate versioned properties. Retirement persists through later intake. Default discovery excludes missing/inaccessible or retired sources; authorized history retains them. Published citations to retained old evidence survive availability changes.

Publication admission loads the page head, proposal, **entire ordered** source membership and route/trust/path identities in one validation snapshot. The first member remains the representative capture ID; all 1–32 members are unique and order-sensitive. Public provenance carries `{representative_capture_id, capture_ids, source_origin}` with the complete ordered list even for one member in new DTOs. Validate/project against every source, including protected literals of secondary sources; never resolve only a representative then infer the rest. Missing/tampered/reordered members fail the whole result, without disclosing the failing source. New source heads set `source_update_available` on a pinned publication until a separately inspected approval creates the next page revision; no automatic citation rewrite.

## 5. Generations, paging and chunk reconstruction

Engine-owned monotonic generations: `retrieval_generation` changes on any candidate set, ranking, head, route, trust, publication, lifecycle, availability or projection change; `authorization_epoch` changes on effective access/grant revocation; `projection_policy_version` identifies redaction/framing policy; `control_epoch` fences collector mutations/purge; `vector_generation` binds a completed optional index to eligibility, projected digests and model/tokenizer/chunker fingerprints. Counters never reset within a Brain incarnation. A migration/rebuild that cannot preserve them changes the incarnation and invalidates continuations.

Search cursor is opaque, purpose-tagged and authenticated. Protected payload binds format version, Brain incarnation, key epoch, normalized query/filter digest, mode requested/used, page limit, ranking implementation fingerprint, effective principal/grants/scope digest, authorization epoch, retrieval generation, exact last-sort tuple, issue time and expiry. Canonicalization uses deterministic canonical JSON, exact UTF-8 query after outer whitespace removal (no hidden case/Unicode normalization), sorted filter sets and explicit defaults. No raw private text is exposed in the cursor. Use an opaque random handle to a bounded private cursor record; authenticate handle/version/epoch with HMAC-SHA256. Store query/scope binding and rank tuple privately. TTL proposal: 15 minutes, 2,000 live handles per Brain; prune expired handles, refuse new allocation with `operation_pending` at capacity. Handles/records are rebuildable local state, excluded from Portable.

Within one read transaction: establish current authorization, validate cursor, compare generation, select/project/order results, and bind next position. Do not retain SQLite transactions between CLI invocations. Lexical ordering uses finite FTS score ascending then record type, record ID, revision ID with SQLite BINARY collation. Store score as exact IEEE-754 binary64 hex in the private record; bind ranking version, reject nonfinite values and normalize negative zero. Compare decoded score numerically in SQL; never page using rounded display scores. Hybrid uses a separately versioned deterministic rank tuple. Fixture gate: at least 201 records with equal scores/ties, repeated traversal, no loss/duplicates in unchanged generation. A write between pages gives `cursor_stale`, never silent restart.

Read projects the **entire** immutable text with current authorization and every provenance member's protected literals before chunking. Exact UTF-8 byte offsets refer to the projected string. Chunks end at scalar boundaries; combining sequences can cross chunks but byte concatenation must reconstruct exactly. Requested target accepts 1–65,536 bytes; a target below the next scalar width permits that one complete scalar, still within the hard encoded envelope bound. Default target 32 KiB, maximum 64 KiB; actual encoded MCP/JSON envelope budgets reduce the chunk further. An empty record returns empty text, offsets zero, complete true and null cursor. Nonfinal chunks make positive progress; `complete` iff no projected text remains and `next_cursor` is null. No truncation marker can stand in for missing middle/end content.

Read cursor privately binds record/revision, projected-content digest, policy version, next byte offset, current authorization binding, Brain/key epoch and expiry. `expected_revision_id` is mandatory: a changed current record yields `revision_changed`; history.show intentionally addresses retained immutable history. Policy/access/lifecycle change invalidates continuation even if stored bytes are unchanged. Validate current authorization on each call before revealing revision differences. A cursor never grants content/history permission.

## 6. Signing custody and untrusted content

Use standard-library cryptographic randomness/HMAC with a private local 32-byte key; no core cryptography/keychain dependency or network. Create under a confined engine operational directory with exclusive creation, mode 0600, parent 0700, owner and single-link checks, no symlinks, fsync file/parent. Key name and record layout are implementation details for the engine owner. Never emit the key in DTOs, logs, reports, Portable or a renderer response. Proposed handle encoding is unpadded base64url of fixed bytes: one format byte, eight-byte big-endian key epoch, 32 random handle bytes, then a 32-byte HMAC-SHA256 over the domain string `open-brain-cursor-v1` plus those preceding bytes. Reject any other decoded length/version or noncanonical encoding. Private records carry purpose and binding data; a handle is not a portable authorization credential. Constant-time MAC verification; bound decoding before allocation. Creation failure refuses new continuation, without degrading legacy first-page search.

Key and records persist across ordinary restart; valid unexpired cursors still require unchanged generation and fresh authorization. Rotation atomically advances key epoch and invalidates **all** earlier cursors (no grace key). Crash recovery resolves pending rotation before access. Missing/corrupt key refuses continuation; authorized recovery creates a new epoch rather than accepting unsigned data. Explicit Brain relocation/rebind invalidates cursor state/key epoch; imported/copied Brain gets a fresh incarnation/key and never imports cursor records. Root device/inode checks remain independent of logical Brain ID. Same-directory restart does not count as relocation. These lifecycle choices are fixed contract requirements; actual cross-process/restart execution is a T05 product gate.

Source text, titles, reasons and history excerpts are untrusted even when they contain fake system messages, tool-call JSON, Markdown fences, terminal escape sequences or role delimiters. Return text only in the typed `content.kind: untrusted_text` slot; adapter-supplied framing is static, outside source control, and says embedded instructions grant no authority. MCP serializes as tool-result data, never system/developer messages or executable tool calls. UI renders inert text/sanitized Markdown without executing HTML or command links; CLI escapes terminal controls at presentation while JSON reconstruction preserves projected text. No source content changes tool definitions, grants, signing material, publication decisions or purge scope. Framing limits authority confusion; it is not a guarantee that a consuming language model will obey. Hostile-content fixture assertions inspect serialization shape and callback noninvocation, not model behavior.

## 8. Purge, leases and failure recovery

Preview scope is explicit `revision` or `logical_source` with exact versions and dependency closure. Revision-only forgetting suppresses that upstream revision; source-wide forgetting suppresses automatic recapture of that namespace. Suppression uses keyed private identity fingerprints (not raw payload text), separate from rotating cursor keys, with a reviewed persistence/export policy. Independent identical manual captures are distinct; shared blobs remain while any retained record owns them. Preview discloses retained independent copies and collateral loss and permits an explicitly broader selection.

Closure inventories source JSON, payload blobs, batches, current/historical SQL, proposal drafts/rejections/approvals/evidence, decisions/publications, canonical pages and tainted history, managed notes/revisions/conflicts, relationships, FTS, text/vector indexes, model-helper in-flight batches, connector staging and collector pending/quarantine/session data. Derived pages citing a forgotten revision are removed whole with tainted history; other independent captures survive. Never silently prune a substring of historical prose.

Writer lease admission is global per Brain with monotonically increasing fencing epoch; bounded acquisition (proposed 2 seconds) returns `operation_pending`. All writers, read materialization, export and optional indexing participate. Reader lease covers authorization through bounded response emission; purge waits for admitted readers to drain before reservation. No lease spans interactive think time. Async helpers hold no write authority and promotion checks fencing/eligibility epochs. OS process locks plus persisted fencing reject stale writers; PID alone is insufficient.

Under lease revalidate preview root, closure, path inode/preimage, head/route/lifecycle generations and collector epoch. Any change returns `preview_stale` before deletion. Journal transitions: `reserved/excluded` → `durable_files_removed` → `projections_removed` → `verified` → `complete`. Reservation installs suppression and exclusion, increments generations/control epoch, cancels or fences in-flight collector/index work, and records cleanup custody. New reads and all exports return `operation_pending` while purge is incomplete. Reservations remain fail-closed on crash; startup recovery runs before reconciliation/import/indexing can resurrect data.

Collector participants acknowledge removal of pending/quarantined/staged bytes under the same control epoch. If offline or unable to acknowledge, retain exclusion and pending status; never claim completion. Lock ordering for later review: Brain lease before collector selection lock; collector fetch occurs without either lock and commit rechecks epoch. Avoid waiting on a collector while holding a lock its acknowledgement needs: reserve under lease, release while awaiting ack, reacquire with fencing for next stage. Requests racing reservation retry only after fresh admission, never blind replay.

Divergent owner-edited managed files or swapped roots block deletion pending a fresh explicit preview; retain visible exclusion, do not unlink arbitrary files. Partial file removal, disk-full, denied unlink, checkpoint/compaction failure and collector interruption are journaled and resumable, never silently successful. Completion requires unique synthetic canary absence from every live store/projection and a newly verified export, including collector staging. Receipts keep only opaque IDs/counts/codes. SQLite WAL/compaction is a measured correctness gate; no SSD/snapshot/backup secure-erasure promise is made.

## 9. Errors, extension boundaries and freeze gates

New domain errors are stable codes with no private path, provider exception, source text or existence-sensitive details. `PluginBridgeFailure.__init__` currently allowlists legacy codes and rejects new codes such as `cursor_stale`; the app owner must extend and test that allowlist, not only `_write_error`. App maps them to CLI JSON `{status:"error", error:{code}}` and nonzero exit; bridge retains its `{ok:false,error:{code},protocol,protocol_version,request_id}` envelope; MCP uses an isError tool result with the same safe code, leaving malformed JSON-RPC errors at the transport layer. Old operations retain existing error vocabulary.

| Code | Trigger / caller action |
|---|---|
| `not_found` | Missing or unauthorized record/history; no existence oracle. |
| `cursor_invalid` | Malformed/MAC failure, wrong purpose/Brain/binding, expiry or unknown handle; discard cursor. |
| `cursor_stale` | Valid cursor but generation/access/policy/key epoch changed; restart explicitly after fresh authorization. Missing retired key may be indistinguishable from invalid and return `cursor_invalid`. |
| `revision_changed` | Authorized record/endpoint precondition changed; refetch/inspect. |
| `preview_stale` | Mutation preview preimages/scope/versions changed; preview and confirm again. |
| `operation_pending` | Lease contention, migration/purge recovery, participant cleanup or cursor capacity; bounded retry/status. |
| `source_revision_conflict` | Same revision key with different canonical submission or conflicting ordering; durable quarantine, not whole-batch success. |
| `model_unavailable` | Required hybrid model/runtime absent/corrupt; lexical capture/search unaffected. |
| `projection_stale` | Required hybrid index not eligible/current; explicit rebuild or allowed fallback. |
| `invalid_arguments`, `unsupported_capability`, `incompatible_runtime`, `response_too_large` | Fail before mutation; negotiate/update/correct bounds. |

Quarantine requires durable validated replayable intake and receipt before advancing checkpoint. A conflicts while B succeeds; checkpoint advances only once every item is committed or transferred to durable custody. Quota exhaustion/disk/auth/global infrastructure faults stop the batch. Ack follows local commit; cancellation/reset fences stale receipts. This outcome is not interchangeable with the current private pending serializer.

Optional retrieval helper receives projected eligible chunks and bounded opaque request IDs over foreground inherited stdio; it cannot access Brain paths, authorize reads, write Brain state or decide forgetting. Engine owns index promotion, eligibility and deterministic mode reporting. `lexical`, `hybrid_preferred`, `hybrid_required` are proposed request modes; response mode is `lexical|hybrid`. Preferred fallback names `model_unavailable` or `projection_stale` in warnings; required fails with that code. T16 measurements/downloads/platform proof remain separately authorized work.

Catalog/service/import consumers must name exact compatible engine/task versions and separate installed/authorized/ready/publicly accepted state. Core remains foreground/offline with optional collector/service/model packages. Owner rebind previews bind root identity and full active relative-path/digest snapshot; new-inode copies require explicit stronger confirmation. Optional document bindings remain private operational data; no path-bearing retrieval DTO. Linux service implementation and native/public claims await their own receipts.

### Source anchors and independent grants

`record.read(record_id=A1, expected_revision_id=A1)` treats a source capture ID as an anchor to its proven logical source, then resolves the current head under current authority. After A1→A2 it returns `revision_changed`, without A1 content; successful refreshed reads return A2 as both `record_id` and `revision_id`. An authorized old anchor with expected A2 may read current A2. An unauthorized or missing anchor returns `not_found` before any head/version detail. Ungrouped legacy captures each remain a distinct single-head source and never imply history membership. A route change re-evaluates current scope, then invalidates continuations through retrieval/authorization generations. Historical exact A1 content is available only through `history.show` with `history-read`; `content-read` never permits a nonhead revision. `history.show` accepts the same read request shape but requires expected_revision_id to be a retained member of the anchor's proven history. A historical canonical revision likewise requires current page eligibility and full source-member projection. `history.list` resolves a source anchor to that same group and a page anchor to page revisions; it does not combine those namespaces.

`source.route` request/receipt and owner-only `relationship.decide`, `relationship.list`, `decision.history` shapes are included in the closed grammar. Endpoint `revision_id` is the expected current retained revision: mutations require both endpoints still eligible/current, otherwise `revision_changed` after authorization. Existing relationship version zero means create; nonzero versions compare-and-swap existing decisions. Replays bind operation_id to exact canonical request digest; divergent reuse fails `invalid_arguments`. Relationship lists and decision history require history-read when later exposed to an agent; M2 initially exposes these three operations only to owner CLI. They are not advertised to bridge agents. Source routing is advertised only with organize authority. These are contract definitions, not new installed commands.
