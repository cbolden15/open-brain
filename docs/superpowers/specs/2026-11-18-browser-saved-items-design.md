# Browser capture and recall in Open Brain

Design for review, 2026-11-18. Baseline commit `60e9d6e`.

## Outcome and scope

While reading an HTTPS page, the owner can save it with a reason, keep several passages, see whether it is already saved and which space contains it, file it, or pick a date to revisit it. Returning to a page lets the owner restore their highlights. Bookmark HTML and plain URL lists feed the same workflow. Search can retrieve the original reason and passages. A Portable Brain round trip preserves these behaviors.

The owner selected the **complete rollout**, including the browser interface, scoped lookup, filing, import, reminders and durable highlights. The **bounded implementation** considered in the intake would extend the documented Shortcut and saved-item folder producer. That remains a useful compatibility fixture for a single capture. Its one-way delivery and first-save-wins rule cannot answer page lookups or retain several highlights.

Recommended public default is Chrome and Open Brain on the same computer. The extension starts a user-installed local helper for each request. Users who keep their canonical Brain on another machine can opt into an authenticated remote connection through the same helper. Both setups are in scope. Ship and document them independently as each passes its acceptance checks. Prove Chrome on macOS first, then qualify Chrome on Open Brain's supported Linux x86_64 target with its own clean-install test. A Mac mini is one deployment example. The public workflow requires neither a particular host model nor a hosted account.

## Browser workflow

1. The owner opens the extension or uses a context-menu action on a selection. Read the active top-level page only on that gesture. Show the normalized page identity for confirmation, the title, a required reason on first save, and the selected passage. Check for an existing save in the configured source and allowed privacy scope. A saved result can show its filing space and its own highlights. An empty or unavailable result must distinguish a successful scoped miss from a disconnected host.
2. Save the page, or attach the selection to an existing save. Offer the current allowed spaces and an explicit filing choice, including leaving a new save unassigned. If filing fails after capture, report the successful save and allow retry of filing on the same record. Never overwrite a previous reason or source on a repeat save. Never elevate a capture’s trust by filing it.
3. On return, opening the extension restores visible highlights. Match exact selected text and surrounding context to a unique passage within the current page. An ambiguous or missing match remains available as a saved quote in extension UI. Keep reasons, space names, notes and record metadata in the extension surface. Avoid background navigation monitoring and page-load lookups. A restored mark must never attach to a low-confidence guess.
4. Bookmark import previews eligible records, duplicates and refusals from a bounded local file. Ask for a batch reason. Snapshot the preview, bind confirmation to it and use the same capture path. Report actual per-item results after interruption or replay. Saved URLs are inputs, never instructions to fetch pages.
5. The owner can set, change, dismiss or clear a revisit date. Keep the date against the page capture and compare against a defined calendar convention (proposed: owner-chosen local calendar date and time zone). Expose a due view on demand. The daily brief may include a scoped, due record reference under its existing cap. Capture reads and filing leave the revisit date alone.

## Ownership, transport and compatibility

The extension handles gestures, import preview and quote matching. A separately installed native messaging host exposes a fixed set of bounded browser operations. Chrome starts the host on demand. Register only the expected extension ID. The host enforces operation grants, permitted source, spaces and tiers from owner-local configuration on every request. The current-tab URL is bound to the gesture by the extension service worker. Page content cannot select a Brain, file path, shell command or authority. Reuse the existing redaction and source identity code. Lookup must project only authorized records, including space metadata and counts. Handle restricted pages, unsupported URLs and host absence in the UI.

On the same machine, the host invokes foreground application services against the owner's selected Brain. For a laptop-to-mini installation, the proposed transport is an owner-configured, authenticated channel to a fixed remote browser operation handler. A restricted SSH command is a candidate requiring a real two-host proof and a separately approved setup before enabling credentials. The endpoint and authorization policy belong to installation configuration. A remote client must never open, copy or sync a live SQLite database. If connectivity fails, show unavailable and allow explicit retry. Reuse the operation ID on an uncertain result. Do not claim a successful save without a canonical acknowledgement. The folder-based producer remains usable independently.

The engine owns page relationships, annotations and revisit state. Use the existing capture identity and saved-item normalization rules within a configured source, including fragment-sensitive identity where the existing contract requires it. Preserve the stored URL's fragment privacy rule. Publish an explicit versioned contract for browser records. Independent annotation IDs belong to a parent capture, and stable mutation IDs distinguish an intentional new highlight from a retried write. Each quote has bounded text, prefix, suffix and optional owner note. Apply existing redaction and retraction policy to anchors and notes too. Keep distinct sources distinct. Legacy v1 records remain readable and ingest with original deduplication behavior. During design validation, prove lookup of an existing v1 save without indexing raw secret URLs or guessing identity from the displayed URL. If that identity cannot be reconstructed safely, expose the compatibility limit and resolve it before extending the feature.

Route through existing space services. Scope lookup and routing separately. Do not pass an owner-wide MCP or plugin capability to the browser. Extend engine migrations and Portable contracts for durable fields, including parent relationships, revisions where applicable, and user-owned revisit state. On restore rebuild derived indexes. A deleted or retracted parent must follow existing visibility, export and history policy for all children. Keep scheduled work and a listening service out of the core.

## Decisions from builder review

- Local and remote installations use the same operation contract. Default to local, with a remote host explicitly selected during setup and visibly identified in the extension. A disconnected remote installation must never silently save into a local Brain. The first remote acceptance pair is a laptop browser and a separately hosted Brain.
- Installation explicitly binds the browser to one saved-item source. The owner can select an existing saved-item source to recognize its prior saves. Compute the lookup key from the current URL using the existing `item_key`, configured source IDs and `SourceRecordKey.delivery_id()`. Prove the key still resolves after ingest and restore with a fresh browser and empty collector cache. A failed proof blocks legacy lookup support.
- Write access is confined to a bound source and privacy tier. Permit creation only when setup gives write authority across the source's complete deduplication domain. Otherwise offer scoped reads only. Revalidate grants on use, including after routing or a policy change. Check parent visibility and write authority for each child mutation. Test hidden and absent identities for equivalent observable responses under partial read scope.
- Browser success requires the engine's terminal accepted result or a verified matching prior acceptance. Show a durable queued submission as pending. Track capture, annotation and filing as separate identified operations with separate results. After interruption recheck their status and replay only unfinished operations, preserving the original IDs.
- Include due revisits in the daily brief after due work follow-ups and before undated work. Keep the existing five-item limit, use a scoped record reference, and preserve other items' relative order. Compare each revisit date using the time zone stored when the owner picked it. Test separately from the UTC dates on work follow-ups.

## Delivery and acceptance

1. **Prove the handoff.** On a disposable browser profile and synthetic Brain, run the real extension through the registered native host, save twice across a lost acknowledgement, then find one accepted item by reason. Prove the allowed page lookup, hidden-source miss and unauthorized caller rejection. On a remote target also prove disconnection, reconnect and remote replay. Stop downstream implementation if the target cannot complete this round trip.
2. **Prove durable highlights.** Save two passages on one page, reopen it, and check both. Exercise duplicate text, changed DOM, retraction and legacy v1 saves. Export, restore into a fresh Brain and repeat lookup, filing and highlight restoration.
3. **Complete organization and import.** Verify scope-safe filing, unassigned saves, preview cancellation, repeated imports, URL normalization and partial failures with a synthetic bookmark file.
4. **Complete revisit and accessibility.** Verify due/dismissed state across a time-zone boundary and after restore. Exercise all browser actions by keyboard, rendered focus, disconnected and empty states, and screen-reader status feedback.
5. **Qualify distribution.** Verify clean install, upgrade, diagnostics and removal of the extension and native host separately from installing core. Run the repository checks, including `make verify`, plus installed browser and native round trips for each advertised target. Publishing artifacts or configuring a live Brain is a separate release action.
