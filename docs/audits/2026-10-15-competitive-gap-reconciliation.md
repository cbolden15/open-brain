## 1. Semantic query retrieval

Active [retrieval.py:128](https://github.com/cbolden15/open-brain/blob/d5cf64e652366dc14a8cf18732f7cb1e82ae4187/packages/engine/src/open_brain_engine/engine/retrieval.py#L128) builds lexical matches; BM25 ranking is at lines184–190. [Catalog metadata:274](https://github.com/cbolden15/open-brain/blob/d5cf64e652366dc14a8cf18732f7cb1e82ae4187/packages/app/src/open_brain/services/catalog.py#L274) explicitly sets semantic_recall false. Existing relevance tests in `packages/app/tests/integration/engine/test_search_relevance.py` cover ranking, authority, redaction, updates and rebuilds, not offline embedding retrieval. Consent-gated `semantic_graph` inference creates reviewed graph suggestions and does not change this search conclusion.

The assessment's “no network or no dependencies” framing is not a forced technical choice. A local model resource can preserve offline inference while adding packaging/runtime costs; a separately distributed optional resource can preserve a small core. Those alternatives need an explicit product/dependency decision and measured quality/size/startup acceptance. The proper shared-engine design would index eligible projected revisions as rebuildable derived state, preserve lexical fallback and all current authority/currentness checks, and test paraphrases plus privacy, edit and withdrawal cases. Adding an ad-hoc synonym list is a smaller option, but cannot substantiate a general semantic-search claim. No model download or design choice was authorized by this audit.

## 2. Retraction and session undo

Main already exposes `source inspect` and `source withdraw --request-file` in [local_entrypoints.py:1187](https://github.com/cbolden15/open-brain/blob/d5cf64e652366dc14a8cf18732f7cb1e82ae4187/packages/app/src/open_brain/services/local_entrypoints.py#L1187). [source_lifecycle.py:65](https://github.com/cbolden15/open-brain/blob/d5cf64e652366dc14a8cf18732f7cb1e82ae4187/packages/engine/src/open_brain_engine/engine/source_lifecycle.py#L65) implements owner-only withdrawal with exact head/lifecycle CAS and replay receipts. It retires supported logical sources from current retrieval while preserving immutable source/history evidence. It does not automatically rewrite reviewed canonical pages. CLI tests cover retained history, exact replay, stale/altered requests and owner authority in `packages/app/tests/integration/services/test_source_lifecycle_cli.py`.

This narrows, rather than closes, the requested feature. Arbitrary captures and session batches are not exposed as that simple owner journey; the source lifecycle endpoint is intentionally not advertised as a general selective-forget feature. A proper extension should build on lifecycle/provenance with previewed capture/session selection, dependency impact, exact confirmation, tombstones and partial-failure recovery. A small wrapper is viable only for captures already represented by supported logical sources; it must not claim universal undo or provider/backups erasure.
