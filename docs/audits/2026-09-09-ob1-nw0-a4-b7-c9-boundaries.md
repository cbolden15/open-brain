# NW0 A4, B7 and C9 boundary proofs

These independently reviewed private prototypes advance NW0. They do not close any whole lane or authorize NW1. All fixtures are synthetic; product model attempts remain zero. Shipping source, dependencies and release artifacts are unchanged.

## A4: authority at the actual handoff

Twelve tests pass: six authority groups and six unchanged A3 controls. A separate reviewer and the coordinator reran them. The SQLite prototype derives the selected prompt from eligible source bodies inside a transaction. It rejects arbitrary caller prompts, stale revisions, inactive consent, exclusions and oversized input before reservation or credential resolution.

A durable dispatch intent is distinct from the actual adapter handoff. After credential resolution, a second transaction rechecks authority and source state. Nonblocking adapter start and cancellation-handle registration share that serialized boundary. Revocation before handoff prevents dispatch; revocation after handoff cancels the handle and prevents publication. Restart cancels unused reservations but charges uncertain intent or handoff records. These are private in-process contracts, not proof of OS authentication, real provider preemption or complete portable-record integration.

## B7: discovery with an explicit missing protocol

Four test groups pass. Seven checks against the unchanged native B5 pair confirm concrete-keg selection, hash-checked exclusive invocation copies and survival of an intervening installation-pointer change. The existing helper passes its twenty frontmatter diagnostic checks. The real helper rejects the proposed capability operation, as expected: the shipping protocol is still absent.

Expected hashes remain trusted inputs to this prototype. Signed distribution metadata, real application launch identity, cross-platform behavior, crash cleanup and protection against malicious writers with the same user identity remain open. Independent review reran the unit groups and inspected existing native receipts without contaminating startup measurements.

## C9: a parent-owned deadline

The coordinator rejected two worker completion claims. A preserved counterexample took about 1.43 seconds despite a 50-millisecond timeout: a socket read could keep receiving bytes without returning control. The corrected prototype uses one owned subprocess per attempt, supervised through nonblocking pipes and a parent monotonic deadline with cleanup time reserved.

Eight test groups pass and were independently rerun. Actual loopback HTTP tests cover the three direct API request shapes, strict terminal/model extraction, chunked bodies, invalid and oversized responses, redirects, cancellation and slow headers/bodies. Slow-header, body and chunked cases each finished in about 303 milliseconds against a 450-millisecond total budget. Cancellation after the server received a request finished in about 51 milliseconds, reaped the child and published no result.

Requests and responses are bounded at 16 KiB, IPC at 32 KiB, with no hidden retry or ambient credentials. This transport is restricted to loopback synthetic servers. TLS, official client selection, real provider compatibility and quality, authority integration, source/evidence validation and exhaustive OS failure behavior are unproven. The conservative one-message output profile requires real-provider validation.
