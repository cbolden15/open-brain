# Desktop companion D0 evidence

Status: D0 accepted locally on macOS arm64

Date: 2026-09-14

Scope: D0 of [the desktop plan](../plans/2026-09-14-desktop-companion.md), on macOS arm64.
The source branch is `feat/desktop-companion-d0`, based on `7bb52f9`. D1 through D4 are not implemented.

## Implemented boundary

The native Tauri host uses packaged React assets and a matched core/Graphify resource pair. It
checks component digests and protocol compatibility, performs a synthetic capture/search/helper
journey, and terminates owned process groups. The renderer has no general shell, executable
selector, database handle, or account-credential interface.

[ADR 0017](../architecture/decisions/0017-desktop-companion-boundary.md) scopes the core's foreground
guarantees and defines the separate companion and future collector. Current product, architecture,
configuration, installation, and contributor documentation are aligned with that boundary.

## Recovery and lifecycle findings

The original bootstrap revoked an active consent when a second client opened the same synthetic
Brain. Independent observation confirmed an active-consent count of one before the second open and
zero afterward, without making a provider request.

Participating clients now hold private session markers. Recovery completes under the registry lock
before another client is admitted. The current marker becomes durable before stale evidence is
removed and remains present if admission or final recovery fails. Registry-version initialization
uses an atomic replacement. Both registry locking and native transport have deadlines.

Independent probes confirmed that a second client waits for delayed recovery and then retains its
consent. A process killed during final recovery leaves a recoverable marker; reopening revokes its
consent. Unit coverage also exercises partial marker/version writes, failed admission, clean final
shutdown, stale markers, and unsupported future SQLite schemas.

The first Rust cleanup path could leave a descendant alive after its immediate parent exited.
Cleanup now waits for the process group and escalates even after the leader is gone. A separate
process probe with a termination-resistant descendant passes. App shutdown also closes admission
to new children, preventing a late spawn from escaping the shutdown snapshot.

## Native proof observations

The initial native window rendered but failed its three-second handshake deadline twice. A separate
measurement of the packaged core returned a valid handshake after 5.457 seconds. Cold startup now
has a 15-second deadline; later local requests retain five-second deadlines.

The final resource layout is `binaries/runtime/bin/open-brain` and
`binaries/runtime/libexec/open-brain-graphify`. This matches the core's helper-discovery rule.
Synthetic data is created outside the app and canonicalized before entering the core's path checks.
The proof executes Graphify; digest validation alone is not treated as helper integration evidence.

The first final bundle reached Graphify but rejected the proof result because its fixture's
`[[Second]]` reference remained unresolved. A canonical direct helper request confirmed two pages
and zero links for that reference, then two pages and one link for the second page's permanent ID.
The fixture now uses that permanent ID. The runtime and helper contracts were not loosened.

The final packaged JSON proof passed with capture `captured`, one search match, Graphify `ok`, and
cleanup confirmed. The real Tauri window displayed the same successful result on launch, repeat,
and relaunch. The result fields and repeat control were visible; the explanatory footer is scrollable.

During an active repeat, the coordinator observed the packaged helper's process group, quit the
native app, and confirmed that both the original app and helper groups were gone. CUA's subsequent
state read relaunched the app under a new PID; that launch also completed successfully. The final
window remains open on its successful proof result.

The bundle contains only the desktop host and the paired resource executables. Its ad hoc signature
passes `codesign --verify --deep --strict`. Accepted executable SHA-256 values:

## Remaining product gates

D0 is isolated from the owner's existing Brain. Older installed clients do not participate in the
new session registry; D1 must enforce a tested runtime/schema compatibility floor before mixed-release
concurrent use. A common `0.1.0` version string alone is insufficient.

Linux x86_64 has a defined AppImage build and CI path. Its clean-host native UI, packaged helper,
and system-library acceptance remain unverified here. Public macOS desktop distribution still needs
its signing, notarization, and installation evidence.

The Unix socket test proves transport primitives only. The collector protocol, durable pause, service
lifecycle, and source permissions remain D3 work. Agent setup, source authentication, recurring
imports, and the requested Jira/email/Drive/iMessage/Slack/GitLab/GitHub integrations are not working
D0 features.
